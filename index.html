Skills

A quality practice, end to end.

FLOW

Core Testing

  • FocusVerifying each feature behaves per its specification.
    ActionSubmit a login form with valid credentials.
    ExpectedSession is created; user is routed to the authenticated view.
  • RiskRecent changes silently breaking previously working paths.
    ActionRe-run prior test suites after a production deploy.
    ExpectedAll previously passing cases still pass without modification.
  • FocusFinding defects no scripted case would anticipate.
    ActionInteract with a new feature without a plan; vary inputs and timing.
    ExpectedUnscripted behavior surfaces gaps beyond the formal test matrix.
  • RiskVisual regressions and interaction quirks across viewports.
    ActionResize the viewport from 320px to 1440px while inspecting spacing.
    ExpectedLayout remains legible and intact at every breakpoint.
  • FocusHow real users complete real tasks without guidance.
    ActionGive a new user a task and observe without intervening.
    ExpectedThe task is completed in under 90 seconds, unaided.
  • RiskStakeholder expectations diverging from delivered scope.
    ActionWalk stakeholders through end-to-end business scenarios.
    ExpectedEvery acceptance criterion is signed off before release.

REQ

API & Integration

  • FocusContract correctness at the boundary between services.
    ActionPOST /users with an invalid email; capture the response.
    Expected400 with a clear validation error; no partial write occurs.
  • RiskServices working in isolation but failing when composed.
    ActionTrigger an order flow that writes to inventory and billing together.
    ExpectedBoth systems remain consistent even when one call fails.
  • FocusIf it can't be reproduced, it can't be fixed.
    ActionFile a defect with steps, environment, expected, and actual.
    ExpectedA developer can reproduce the issue on the first attempt.

TARGET

Platforms

  • RiskBehavior diverging across browsers despite shared specs.
    ActionRun the critical path in Chrome, Firefox, and Safari.
    ExpectedBehavior is consistent across all three engines.
  • RiskGesture, orientation, and network variance across devices.
    ActionRotate the device mid-flow and toggle network connectivity.
    ExpectedState persists; the app handles interruptions gracefully.

OPS

Tools

  • FocusCollection-based test organization that scales with the API.
    ActionOrganize requests into folders and apply environment variables.
    ExpectedA new teammate can run the full collection without setup.
  • FocusUnified test code targeting both iOS and Android.
    ActionRun the same test suite against iOS and Android builds.
    ExpectedBoth platforms pass without platform-specific forks in test code.
  • FocusTraceability from requirement to defect to release.
    ActionLink a bug to its source story and verification build.
    ExpectedEvery defect traces to a story and a specific build number.
  • FocusLayout inspection and network profiling during test runs.
    ActionCapture a profiler trace while reproducing a slow interaction.
    ExpectedThe bottleneck is identified with measurable evidence, not guesswork.

TRACE

QA Process

  • FocusScope, risk, and exit criteria written before execution begins.
    ActionDraft a plan covering scope, entry/exit criteria, and risks.
    ExpectedThe plan is reviewed and signed off before test design starts.
  • FocusAligning testing depth to product risk, not to habit.
    ActionMap product areas to risk levels and assign test depth accordingly.
    ExpectedHigher-risk areas receive deeper coverage; lower-risk areas, less.
  • FocusWhere testing fits in each delivery phase.
    ActionIdentify quality checkpoints in every SDLC phase.
    ExpectedEach phase has a defined quality gate with measurable criteria.
  • FocusA disciplined lifecycle from planning to closure.
    ActionMove a feature through plan, design, execute, and closure stages.
    ExpectedEach stage produces defined deliverables and traceable outputs.
  • FocusAnyone on the team should be able to execute the case.
    ActionWrite a case with preconditions, steps, and expected result.
    ExpectedA tester unfamiliar with the feature can follow it without questions.

LOAD

Advanced Testing

  • RiskSystems that pass functional tests but buckle under real load.
    ActionApply sudden traffic bursts (spike) and prolonged load (endurance).
    ExpectedResponse times stay within SLA; no memory leaks over time.
  • FocusVerified capacity under expected production traffic.
    ActionDrive traffic to expected peak volume for 30 minutes.
    ExpectedSystem sustains the load with stable throughput and error rate.
